> **이 파일은 `tools/overview.py` 가 원장에서 만든다.** 서술은 코드 안에

## 1. 무엇을 묻는가

한국어 토크나이저를 바꾸면 무엇을 얻고 무엇을 잃는가. **어휘 크기를**
**유지한 채** 토큰을 치환하는 수술(T2b)을 걸고, 같은 코퍼스·같은 예산으로
CPT 한 뒤, 원본 토크나이저 통제군(C0)과 비교한다. 주 비교의 168.5MB는
**동일 원문량**을 맞춘 것이며, 조건별 토큰 수·update 수가 달라 동일 연산량이 아니다.

핵심 지표는 **BPB (bits per byte)** 다. token PPL은 예측 단위가 달라
토크나이저 사이에 직접 비교할 수 없다. 관계는
`log2(PPL_token) = BPB / (tokens/byte)`이고, BPB는 분모를 원문 바이트로 둔다.

회복률은 이렇게 정의한다 (`docs/RULES.md` 14b).

```
R = (B0 - Bf) / (B0 - Cf)
  B0  수술 직후 · 학습 전 한국어 dev BPB
  Bf  같은 모델을 CPT 로 예산만큼 돌린 뒤
  Cf  통제군 C0 (원본 토크나이저, 같은 코퍼스 · 예산 · 스케줄)
```

R은 기존 사전 등록을 보존하기 위한 보조 지표다. 해석은 **절대 B0/Bf/Cf와
최종 잔차 Bf-Cf를 먼저** 하고, R의 유사성만으로 불변성이나 공통 메커니즘을
말하지 않는다 (`docs/RULES.md` 14b amendment).


## 4. 2차 결과 — 무엇이 회복을 정하는가

1차(코사인 LR, seed42)에서 세 조건의 최종 R 은 N=30k 65.4% ·
등토큰 68.2% · N=10k 65.9% 였다. 2차는 그 종점을 무엇이 정하는지
물었고, **사전 등록한 가설 셋 중 둘이 반증됐다.**

### R1 — 시험한 두 손상 구성의 회복 궤적은 달랐다

토크나이저를 안 바꾸고 임베딩 **행 40개만** 망가뜨린다. 손상 배율은 T2b 와
맞췄다 (학습 없는 보정으로 K 를 골랐다).

| 조건 | 학습 전 | 학습 후 | 통제군 | R |
|---|---:|---:|---:|---:|
| 행 40개 손상 (40MB) | 2.3758 | 1.4846 | 1.1464 | **72.50%** |
| T2b 치환 (40MB) | 2.3808 | 1.7539 | 1.1464 | **50.79%** |

같은 aggregate 초기 손상 배율에서 **21.71%p** 벌어진다.
그러나 행 수·노출·토큰화가 함께 달라 이 차이를 토크나이저 치환 자체에
귀속할 수 없다. **시험한 두 구성의 회복 궤적이 다르다**까지만 방어한다.

> **남은 교락:** 두 조건은 손상 배율만 같고 **행당 노출** 과 **손상 행 수** 가
> 다르다. 2026-09-19 에 시험한 손상 방식과 K<=30,000 탐색에서는 노출과
> 손상 배율을 동시에 맞추지 못했다. 다른 손상 방식까지 불가능하다는 뜻은 아니다.

### Q7 — 17.5MB에서 큰 tied 효과는 관측되지 않음

`lm_head` 를 임베딩 사본으로 복제해 tie 를 끊고(수술 전후 forward 가 비트
단위로 같은 것을 확인) 같은 실험을 돌렸다. 17.5MB × 3 seed.

```
R(untied) 42.70%   R(tied) 42.26%   차이 +0.44%p
```

seed 별 paired 차이 (untied - tied): 42 +0.436%p · 123 +0.457%p · 2026 +0.440%p.
paired seed 차이의 탐색적 t(df=2) 95% CI는 [+0.417, +0.471]%p다. 사전 등록한 효과 크기
바닥 ±5%p 안이지만 n=3 정규성 가정의 사후 구간이라 일반적 동등성 증명은 아니다.
forward 동일성은 시작 함수만 같다는 뜻이다. untie는 파라미터를 27.6% 늘리고
입력·출력 gradient 공유를 끊으므로 장기 학습 동역학이 같다는 결론은 아니다.

### R5 — 상수 LR 에서 유한 예산 잔차가 줄었다

코사인 대신 **상수 LR** 로 같은 예산을 돌렸다. 감쇠만 빼고 나머지는 같다.
통제군도 상수 LR 로 다시 돌렸다 (조건이 바뀌면 대조군도 다시 잰다).

| | 코사인 | 상수 LR |
|---|---:|---:|
| T2b 한국어 BPB | 1.5671 | 1.4729 (3 seed) |
| C0 한국어 BPB | 1.1375 | 1.1274 |
| 회복률 R | 65.44% | **72.42%** |

더 직접적인 종점 잔차 `Bf-Cf`는 0.429555 -> 0.345543,
**0.084012 BPB 감소**다.

σ_R = 0.026%p (3 seed). 등록 예측은 "71~75%" 였고 경쟁 등록
("68.5% 이하")은 기각됐다.

**헤드라인이 바뀐다.** 168.5MB의 코사인 종점은 회복 한계가 아니었다.
상수 LR이 그 유한 예산 종점을 개선했고 C0도 좋아졌다. 무한 예산 점근선이나
일반적인 "벽"은 이 실험으로 식별하지 않았다.

## 5. 한자 프로브 (D1~D3)

T2a 가 제거한 30,000개 중 13,310개(44.4%)가 한자 포함 토큰이었다. 빈도
필터의 부수 효과이고, 절단면은 **간체 전용자** 쪽으로 치우쳐 정자(國 無 韓)는
남았다 — **사후 관측이라 예측 근거로만 쓰고 결과로 인용하지 않는다**
(`docs/PLAN.md` 사전 등록). 사전 등록한 세 측정 — 한자가 밀집한 부분집합
(787문서)의 tok/byte·BPB 와 KMMLU — 으로 T2a 와 C0 를 비교했다.

| | C0 | T2a | T2b |
|---|---:|---:|---:|
| 한자 밀집 BPB | 1.2607 | 1.2610 | 1.6734 |
| KMMLU 정확도 (1,900문항) | 0.3153 | 0.3132 | 0.2368 |

한자 밀집 BPB 는 T2a +0.03% (등록 경계 ±5%, 이 부분집합의
σ 없음). KMMLU 는 -0.21%p, paired 95% CI [-1.05, +0.58]%p 로
**등록한 동등성 경계 ±2%p 안** 이다 — 그 checkpoint · 1,900문항의 판정이고 seed
불확실성과 지식 손상 부재를 뜻하지 않는다. C0 가 찍기(25%)보다 약 6.5%p
위라 **측정 감도가 낮을 수 있다는 우려** 가 있다.
오염 검사 범위: 우리 CPT 풀(앞 50,000문서)과 질문 본문의 문자 13-gram(공백 제거 · NFKC 소문자) 겹침만 — 덮임 50% 이상 2 / 1,900문항 (`contamination.md`). Qwen 사전학습 · 의역 · 문자 13개보다 짧은 겹침은 검사하지 않았다.

## 6. 3차 설계 — 2026-09-19 외부 검토 amendment

```
우선  학습 회계·BPB 위치 대응·split/중복 감사를 닫고 N=30k C0/T2b 대응 seed
수정  동일 update/토큰 예산 비교와 신규 행 warm-start 대조군
수정  WSD — cooldown 20%도 총 168.5MB 예산 안의 비용으로 센다
후순위 500MB — 유한 구간 곡선 연장으로만 보고, 점근선 판정은 하지 않는다
후순위 KMMLU 39과목 · 1.5B — 핵심 재현과 compute 대조 뒤
취소  R 유사성 기전 검정(P3-C), CPT 행 이식을 완벽한 초기화 상한으로 읽는 P3-E
```

### 3차 결과 (amendment 2~6주차 + Final Test, 2026-10-19)

잔차 d = BPB(T2b) - BPB(C0), 한국어 dev, 상수 LR. 같은 seed 끼리 짝짓는다.

```
2주차  같은 원문 168.5MB   d 평균 +0.345679 (seed 3쌍 SD 0.000235)
3주차  같은 update 1,523   d 평균 +0.321189 (SD 0.000168) · 줄어든 몫 rho 7.2% (seed 별 rho 의 평균, 분모는 upd run 자신의 168.5MB 지점 d +0.345995. 2주차 d 로 나누면 7.08%)
4주차  신규 행 warm-start   d +0.357348 vs 직접 +0.345639 -> delta -0.011709 (gate +0.010 미달, seed 42)
5주차  대표 조건 재학습      d +0.345564  문서 구간 [+0.336924, +0.354955]
6주차  WSD(마지막 20% 감쇠)   T2b +0.010403 (악화) · 잔차 +0.009184 (악화), seed 42
Final  본 적 없는 5,067문서      d +0.348637  문서 구간 [+0.345985, +0.351245] -> 확증 (seed 42 대표 쌍)
       같은 체크포인트 영어 d +0.008230 · 코드 d +0.009895 (압축은 거의 그대로인데 BPB 는 T2b 가 조금 나쁘다)
```

**같은 update 수를 받아도 잔차의 대부분이 남았다** — 시험한 update 보정만으로는
같은 원문량 조건의 격차가 해소되지 않았다. 더 큰 예산에서의 회복과 원인별 기여도는
확인하지 않았다 (rho 는 감소율이지 원인의 기여율이 아니다). 같은 총예산 안에서 새 행을
먼저 학습시키는 배분(warm-start 20%)은 직접 CPT 보다 나빴고, 시험한 WSD(마지막 20% 감쇠,
바닥 10%) 도 상수 LR 보다 나빴다 (둘 다 seed 42, 그 recipe 의 결과).
문서 구간은 dev 문서 표본의 불확실성만 담고, seed 불확실성은 SD 가
따로 낸다. Final Test 는 선택 규칙을 먼저 고정하고(`docs/PLAN.md` "5주차 동결" D)
대표 둘만 한 번 열었다 — 위 마지막 줄이 그 결과다.

## 7. 방법론에서 지키는 것

- **사전 등록.** 예측 · 판정 경계 · 효과 크기 바닥을 돌리기 전에 커밋한다.
  결과를 보고 경계를 옮기지 않고, 옮겨야 하면 그 사실을 날짜와 함께 적는다
- **효과 크기 바닥 + 2σ.** 바닥은 R 에 5%p (Q7) · BPB 에 0.005 (6주차). σ 는 판정 대상의
  seed 표본 SD 이고 짝 비교에는 대응 차이의 SD 를 쓴다. 2σ는 등록 휴리스틱이지 95% CI가 아니다
- **R 은 보조 지표다.** R = 1 - (Bf-Cf)/(B0-Cf) 는 CPT 후 통제군을 목표로 간격을 얼마나
  닫았나이지 초기 손상의 복구율이 아니다 — B0 와 Cf 에 함께 의존한다. 1차 지표는 d = Bf-Cf
- **조건이 바뀌면 통제군도 같은 조건에서 다시 잰다** (R5 의 상수 LR C0)
- **결과는 코드가 원장에 쓴다.** 마크다운에 손으로 옮기지 않는다
- **append-only 원장** — 실패한 run 도 지우지 않는다 (fail · abort 포함)
- 커밋 훅이 규칙을 집행한다 — 결과 커밋에 코드가 섞이면 거부된다

## 8. 알려진 한계 (전부 문서에 적혀 있다)

- **0.5B 한 모델.** 1.5B 는 수술 손상만 쟀고 CPT 회복력은 미측정
- **seed 수가 조건마다 다르다.** 3 seed: 노이즈 플로어 · Q7 · R5 · 상수 LR C0/T2b 쌍 ·
  같은 update T2b. seed 42 하나: 1차 코사인 run · R1 · warm-start · WSD · Final Test 체크포인트
- **dev 가 닳았다.** 초기화도 N 도 dev 에서 골랐다. Final Test 는 2026-10-19 에
  대표 둘(상수 LR C0 · T2b, seed 42)만 한 번 열었다 (`final-test-opened`)
- **CPT 코퍼스와 Qwen 사전학습은 모두 Common Crawl 계열일 수 있다.** 실제
  중복률과 편향 방향은 측정하지 않아 알 수 없다
- **평가 문항 오염 제거가 구현되지 않았다.** 2026-09-19 에 따로 셌다.
  오염 검사 범위: 우리 CPT 풀(앞 50,000문서)과 질문 본문의 문자 13-gram(공백 제거 · NFKC 소문자) 겹침만 — 덮임 50% 이상 2 / 1,900문항 (`contamination.md`). Qwen 사전학습 · 의역 · 문자 13개보다 짧은 겹침은 검사하지 않았다. 겹침이 곧 오염인지는 판정하지 않았다
- **도메인 라벨 정확도가 ~55%** 라 도메인별 수치를 인용하지 않는다
- **ZeTT 를 못 돌렸다.** CPT 행 이식은 몸통-행 상호적응을 깨는 compatibility
  진단일 뿐, 완벽한 초기화 상한이나 ZeTT 대체 baseline이 아니다
- 문서 bootstrap 은 문서 단위 paired 다. 사이트 · 출처 군집은 고려하지 않았다
- 수술 코드 경로의 명시적 no-op 대조(아무것도 안 바꾸는 수술)는 하지 않았다
- 학습 wall-clock 이 오염됐다 (데스크톱이 GPU 를 함께 썼다). 속도 주장에
  쓰지 않는다. BPB 는 영향 없다

## 9. 초기화 baseline 의 위치

E1(merge 부품 평균)은 **검증된 범위에서만 FVT와 같다** — 표면형을 원본 토크나이저로
다시 토큰화하면 정확히 그 merge 부품 두 id 가 나오는 25,821개에서 100% 일치했다 (같은 두
원본 행의 평균이므로 벡터가 같다). 나머지 4,179개(13.9%, **어휘 항목 비율이지 실제 출현
비율이 아니다** — 출현 비율은 미확인)는 표면형이 유효 UTF-8 이 아니라 **우리의 standalone
재토큰화 경로에서** FVT 가 정의되지 않는 경우이고, 거기서는 merge 계보로 확장한다.
바이트 단위 평균과의 중앙값 코사인 0.520 · 0.171 은 서로 다른 토큰 집합의 값이라 초기화의
우열을 뜻하지 않는다.

E2(역빈도 가중)는 **FOCUS 가 아니다** — 가중치 출처가 유사도가 아니라 빈도다.

선행 연구에는 continued-BPE, leaf pruning, 평균 subtoken 초기화, embedding-only
warm-start, 저예산 tokenizer swapping이 이미 있다. 따라서 novelty는 개별 기법이
아니라 **한국어 소형 모델·고정 vocabulary 크기·제한 CPT에서의 회복 곡선과
비용-품질 trade-off를 통제축별로 측정한 증거**로 한정한다.

## 10. 운영 환경 — 장비 한 대를 원격으로 돌린다

실험은 **데스크톱 워크스테이션 한 대** (RTX 5070 Ti 16GB) 에서만 돈다.
클러스터도 클라우드도 없고, 학습을 두 개 동시에 띄우지 않는다 — 그래서
일정표의 시간이 곧 실제 대기 시간이다.

긴 run(3~11시간)을 책상 앞에서 지킬 수 없으므로 **원격 접속** 을 붙여 뒀다.

```
사설 메시 VPN (Tailscale)   기기끼리만 닿는 사설망. 포트를 공개하지 않는다
OpenSSH 서버               그 망 안에서만 접속. 자동 시작 서비스
쓰임                       run 시작 · 진행 확인 · 원장 tail · 중단
```

**기기 이름 · 주소 · 키 · 계정 정보는 저장소에 넣지 않는다.** 저장소는 공개를
전제로 쓰고 있고, 접속 정보는 실험의 재현성과 무관하다. 재현에 필요한 것은
`env/ENV_SNAPSHOT.tsv`(드라이버 · 라이브러리 버전 해시)와 원장이다.

한 대뿐이라는 제약이 설계를 여러 번 바꿨다 — 7B 를 포기하고 0.5B 에서 깊게
판 것, 비교 실험을 40MB 로 줄인 것, Q7 게이트에서 6시간짜리 본편을 취소한 것이
전부 여기서 나온다.

## 당신이 할 일

이 설계와 결과를 읽고 **틀린 곳 · 과잉 주장 · 빠진 대조군** 을 찾아라.
칭찬은 필요 없다. 내가 놓친 것을 찾는 것이 목적이다.

우선순위가 높은 순으로:

1. **주장이 데이터를 넘는 곳.** 이 실험 설계로는 말할 수 없는데 말하고 있는
   문장이 있으면 그 문장을 인용하고, 무엇이 더 필요한지 적어라
2. **빠진 대조군.** "이 비교에는 X 조건이 하나 더 있어야 한다" 가 있으면
   그 조건이 무엇을 가르는지까지 적어라
3. **지표와 정의.** 회복률 R 의 정의(1절)가 결론을 실제로 지탱하는가.
   분모·분자·시점 선택이 결과를 유리하게 만드는 구석은 없는가
4. **통계.** 효과 크기 바닥 5%p + 2σ 규칙, seed 1개인 run 들, bootstrap CI
   사용이 적절한가. 과소·과대 주장이 되는 지점은 어디인가
5. **선행 연구와의 거리.** 이 결과가 이미 알려진 것과 겹치는 부분이 있으면
   구체적인 논문과 함께 지적하라. "새롭지 않다" 는 판단도 환영한다
6. **투고 가능성.** 이 정도면 워크숍/단편 논문이 되는가. 안 된다면 무엇이
   더 있어야 되는가 (마감은 7주 뒤다. 장비는 GPU 한 대뿐이다)

## 규칙

- **추측으로 숫자를 만들지 마라.** 개요에 없는 수치가 필요하면 "이 값이
  없어서 판단 못 한다" 라고 적어라. 없는 값을 가정해 논증하지 마라
- **코드를 새로 써 주지 마라.** 실험 설계와 주장에 대한 검토만 필요하다
- **우선순위를 매겨라.** 지적이 10개면 "이것부터 고쳐라" 순으로 정렬해라.
  치명(결론이 흔들림) / 중간(문장 수정) / 사소 로 나눠라
- 개요는 한국어이고 답도 한국어면 좋다. 용어는 영어 그대로 써도 된다
- 이 프로젝트는 **부정 결과를 결과로 보고하는 것** 을 원칙으로 한다.
  "실패한 실험이 많다" 는 지적이라면, 그것이 왜 문제인지까지 적어라
