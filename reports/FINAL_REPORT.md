# KoTokenLab — 최종 보고서

> **1차 완료 (2026-09-02).** 사전 등록 질문 Q1~Q6 와 유효 범위 Phase 6(A/C/E)이
> 모두 닫혔다. 모든 수치는 `experiments/` 원장에서 읽었다 — 손으로 옮겨 적은
> 것은 없다.

한국어 특화 토크나이저가 LLM 의 언어모델링 품질, 학습 효율, 추론 비용에
미치는 영향을 단일 RTX 5070 Ti 16GB 에서 통제된 실험으로 분석한다.

기간 2026-08-29 ~ 2026-09-02 (5일) · Qwen2.5-0.5B (스케일 확인 1.5B) · seed 42

---

## 0. 한 문단 요약

**압축은 설계대로 됐고, 품질은 따라오지 못했으며, 그 대신 추론 비용을 샀다.**
크기 보존 치환(T2b)은 한국어 토큰을 30.2% 줄이고 영어·코드를 거의 건드리지
않는다. 그러나 동일 CPT 후 한국어 BPB 가 원본보다 37.8% 나쁘고, 가장 유리한
등토큰 조건에서도 34.7% 나쁘며, **1.5B 에서는 상대적으로 더 나쁘다.**
반면 prefill 은 35~41%, KV cache 는 30%, TTFT 는 같은 폭으로 줄고, 같은 문맥
창에 44% 더 많은 글이 들어가며, 초당 처리 문서가 1.60배다.
**권고는 조건부다** (§7).

**가장 값진 결과는 세 번의 반증** 이다 (§4). 노름 보정 · Embedding Alignment ·
노출 부족 — 전부 우리가 세운 가설이고 우리가 무너뜨렸다. 그리고 65% 회복
한계의 정체는 **아직 모른다** — 최적화 문제가 아니라는 것까지만 왔다 (§8.2).

## 1. 무엇을 물었나 — 사전 등록 질문

실험 전에 여섯 개를 고정했다. 각 질문은 `개선 / 구별 불가 / 악화` 중 하나로만
답하고, 경계는 **조건별** 노이즈 플로어의 2σ 다.

| # | 질문 | 답 | 근거 |
|---|---|---|---|
| Q1 | 한국어 토큰을 얼마나 줄이는가 | −30.2% | [`t2_sweep.md`](tables/t2_sweep.md) |
| Q2 | 영어·코드 regression | 영어 −0.0%, 코드 −0.8% | 같음 |
| Q3 | 교체 직후 얼마나 무너지는가 | 2.06배 (부품 평균) | [`precpt_bpb.md`](tables/precpt_bpb.md) |
| Q4 | 동일 CPT 후 원본보다 좋아지는가 | **아니오** (+37.8%) | [`cpt_main.md`](tables/cpt_main.md) |
| Q5 | 축소(T2a)와 치환(T2b)은 다른가 | **결정적으로 다르다** | 같음 |
| Q6 | 추론 비용은 얼마나 개선되는가 | prefill −35~41% | [`system_bench.md`](tables/system_bench.md) |

## 2. 방법 — 이 숫자들을 왜 믿을 수 있는가

- **사전 등록.** 질문과 판정 기준을 결과 전에 고정. Phase 4·5·6 은 예측까지
  미리 적었다. 한 번은 기준 자체가 나빴는데(어떤 값도 통과 못 하는 2σ)
  완화하지 않고 그 사실을 기록했다
- **조건별 σ.** seed 42/123/2026 으로 조건마다 노이즈 플로어를 잰다.
  σ 는 조건에 따라 21배까지 다르다 — 하나로 퉁치면 차이를 그만큼 과대 검출한다
- **Equal-Raw-Data.** 예산을 토큰이 아니라 원문 바이트로 센다. 등토큰은
  보완 축으로 따로 잰다 (스펙 §31~33)
- **BPB, PPL 아님.** 토크나이저가 다르면 PPL 은 비교할 수 없다
- **append-only 원장.** 실패한 run 도 지우지 않는다. 계보 해시는 손으로 적을
  수 없다 — 훅이 원장과 대조해 거부한다
- **훅과 CI.** 커밋 규칙·원장 무결성·금지 경로를 이중으로 막는다
- **Final Test 잠금.** 한 번도 열지 않았다

전체 규약은 [`../docs/RULES.md`](../docs/RULES.md), 스펙과 다르게 한 것은
[`../docs/DESIGN_DELTA.md`](../docs/DESIGN_DELTA.md).

## 3. 무엇을 만들었나

### 3.1 코퍼스

한국어 118.7만 문서 4.73GB (FineWeb-2), 영어 51,960 · 코드 30,216 대조군.
`phase1-tokenizer-freeze` 로 고정. 도메인 라벨은 블라인드 감사 3회 결과
**news/기타만 신뢰 가능** — 한국어 내부 세분화는 ~55% 다.

### 3.2 토크나이저 수술 — 두 조건

| | 하는 일 | vocab | 선행 연구 |
|---|---|---|---|
| **T2a** | 안 쓰이는 토큰 30,000개 제거 | 121,728 | 있음 (vocab pruning) |
| **T2b** | 같은 자리를 한국어 토큰으로 **치환** | 151,936 유지 | **우리 것** |

T2b 의 기증 토큰은 **인접쌍 채굴** 로 고른다 — Qwen 으로 토큰화한 한국어에서
붙어 나오는 쌍을 세고, 새 토큰 하나 = merge 하나 = 슬롯 하나로 바꾼다.
v2 는 pretokenizer 세그먼트 **안쪽** 쌍만 센다. 경계를 넘는 쌍은 절대 발화하지
않기 때문이다 — 이 한 가지로 n=30,000 이 v1 의 n=50,000 을 이긴다.

### 3.3 임베딩 초기화

| 방법 | 한국어 BPB |
|---|---:|
| 기준선 (수술 없음) | 1.1569 |
| E0 무작위 | 5.0148 |
| **E1 부품 평균 (채택)** | **2.3803** |
| E1 + 노름 보정 | 3.0017 |
| E2 역빈도 가중 | 2.4282 |

## 4. 무엇이 반증됐나

이 프로젝트의 실체는 여기 있다. 셋 다 우리가 세운 가설이고 우리가 무너뜨렸다.

### 4.1 노름 보정이 초기화를 공정하게 만든다 → 반증

평균은 노름이 줄어드니 원본 분포에 맞춰 키워 주면 나아질 줄 알았다.
한국어가 2.3803 → 3.0017 로 나빠졌고 **영어까지 0.8126 → 0.9448 로 함께**
나빠진 것이 기전을 알려줬다. `tie_word_embeddings` 라 그 벡터가 출력 로짓
방향이기도 해서, 키우면 학습 안 된 토큰을 모델이 더 자신 있게 예측한다.
**작은 노름은 보호 장치였다.**

### 4.2 Embedding Alignment 로 예열한다 → 폐기

스펙 §25 가 요구한 단계다. 3라운드 탐침 끝에 **손해를 안 내면서 제 일을 하는
lr 이 없다**는 것을 확인하고 통째로 뺐다. 같은 예산에서 그냥 CPT 하는 쪽이
한국어를 7.2배 더 회복시킨다. 전체 표: [`alignment_probe.md`](tables/alignment_probe.md)

### 4.3 노출이 부족해서 못 배웠다 → 반증

새 토큰의 중앙값 발화가 143회뿐이었다. 토큰을 1/3 로 줄여 노출을 4.4배(623회)로
올렸더니 **회복률이 65.4% → 65.9% 로 안 움직였다.**

그리고 더 강한 사실이 나왔다 — **회복률 곡선이 세 조건에서 겹친다.**

| 예산 | N=30k(168MB) | N=30k 등토큰(241MB) | N=10k(168MB) |
|---:|---:|---:|---:|
| 20MB | 51.2% | 50.9% | 51.5% |
| 40MB | 59.0% | 59.1% | 59.4% |
| 80MB | 64.3% | 65.6% | 64.7% |
| 최종 | 65.4% | 68.2% | 65.9% |

손상 크기도 노출도 다른데 회복 *비율* 이 1%p 안에서 같다. 회복률은
**예산만의 함수** 로 보인다.

같은 원문 168.5MB, 같은 스케줄, 다른 것은 토크나이저뿐.

| 조건 | 한국어 | 영어 | 코드 | 토큰 | 압축 |
|---|---:|---:|---:|---:|---:|
| C0 원본 | 1.137540 | 0.813282 | 0.440420 | 49,922,048 | — |
| T2a 제거만 | 1.136817 | 0.813393 | 0.441564 | 49,922,048 | +0.0% |

## 6. 핵심 결과 — 시스템

| 원문 | 토큰 Δ | prefill Δ | 증폭 |
|---:|---:|---:|---:|
| 5,000자 | −31.1% | −34.7% | 1.12x |
| 40,000자 | −30.6% | −41.3% | 1.35x |

**토큰을 30% 줄이면 시간은 35~41% 준다.** prefill 이 초선형이라 증폭 계수가
길이와 함께 오른다. KV cache 는 토큰과 정확히 선형(−30%), TTFT 는 40,000자에서
728ms → 428ms, 같은 16,384 토큰 창에 한국어가 **44.1% 더** 들어간다.

계측기는 널 대조군 둘로 검증했다 — 차이가 나면 안 되는 자리에서 0.1~0.5%.

## 7. 권고

> **0.5B 규모에서 크기 보존 치환은 언어모델 품질을 희생하고 추론 비용을 산다.**
> 긴 한국어 문서를 다루고, 지연·메모리·문맥 길이가 병목이며, 품질 저하를
> 감수할 수 있을 때만 성립한다.
>
> **품질이 중요하면 T2a 다.** 임베딩 27.1M(5.5%)과 메모리 51.8MB 를 품질 손실
> 없이 줄인다. 압축 이득은 없다.
>
> **더 큰 모델을 쓴다고 나아지지 않는다.** 1.5B 에서 손상 배율이 오히려
> 커졌다 (§8.1). 다만 회복력은 아직 안 쟀다.
>
> **배치 튜닝으로 대신할 수 없다.** 긴 문서에서는 시퀀스 하나가 이미 GPU 를
> 포화시켜 배치가 처리량을 사지 않는다 (§8.3). 처리량 1.60배는 압축에서 온다.

## 8. 유효 범위 — Phase 6

코어의 결론이 어디까지 적용되는지를 정하는 후속. 사전 등록은
[`../docs/PLAN.md`](../docs/PLAN.md) "Phase 6".

### 8.1 스케일 — 완료 (2026-09-02)

Qwen2.5-1.5B 에 같은 수술을 걸었다 (vocab·merges 가 0.5B 와 완전히 같다).

| | 기준선 | 수술 후 | 손상 배율 |
|---|---:|---:|---:|
| 0.5B (임베딩 27.6%) | 1.1569 | 2.3803 | 2.058배 |
| 1.5B (임베딩 15.1%) | 0.9921 | 2.3060 | **2.324배** |

**예측이 틀렸다.** 임베딩 비중에 비례해 1.58배로 줄 것으로 봤는데 오히려
커졌다. 이유는 분모에 있다 — **수술 후 상태는 스케일과 거의 무관하고**
(−3.1%) 기준선만 좋아진다(−14.2%). 큰 모델은 잃을 것이 더 많고, 수술은 둘 다
거의 같은 자리로 되돌린다.

즉 **부정 결과는 스케일에서 약해지지 않는다.** 손상이 파라미터 몫의 문제가
아니라는 뜻이기도 하다.

**답하지 않은 것**: 1.5B 가 CPT 로 더 잘 회복하는지는 모른다. 이 측정은
손상이지 회복력이 아니다.

### 8.2 기울기 — 완료. 신호는 있는데 못 따라간다

`train_curve` 의 `grad_norm_emb` / `attn` / `ffn` 을 처음으로 채웠다.

| 예산 | ko BPB | emb | attn | ffn | lr |
|---:|---:|---:|---:|---:|---:|
| 20MB | 1.7441 | 4.78 | 2.09 | 2.42 | 9.78e-06 |
| 100MB | 1.5726 | 3.39 | 1.86 | 2.30 | 4.31e-06 |
| 160MB | 1.5675 | 2.98 | 1.90 | 2.14 | 1.06e-06 |

**예측대로 임베딩 기울기가 죽지 않는다.** 끝까지 attn 의 1.57배로 남는데,
같은 구간에서 BPB 는 100MB 이후 0.005 밖에 안 움직인다. **모델은 신호를
끝까지 받고 있는데 못 따라간다 — 병목은 최적화가 아니다.**

80MB → 100MB 에서 기울기가 오히려 오른다(3.05 → 3.39). 같은 구간에서 lr 은
6.0e-06 → 4.3e-06 으로 떨어진다. 업데이트는 `lr x grad` 이므로 **LR 이 회복을
끊고 있다는 방증** 이다.

**덤으로 같은 시드 재현성을 처음 쟀다.** 이 run 은 §5 의 T2b run 과 tag 만
다르다. 9개 지점 최대 편차 0.000421 로 시드 간 sigma(0.001234)의 34% 다 —
**sigma 를 시드 분산으로 잡은 것이 과소평가가 아니었다.**

### 8.3 배치 처리량 — 완료. 처리량은 배치가 아니라 압축에서 온다

```
동시 처리 수   C0 20  ->  T2b 28      1.40배   (예측 1.43배)
정점 처리량    3.85   ->  6.18 seq/s  1.605배
배치1 prefill  265.8  ->  163.2 ms    1.629배
```

**예측이 절반 맞았다.** 동시 처리 수는 KV 절감만큼 늘었다. 그러나 "처리량
이득은 그보다 작다" 는 틀렸다 — 1.605배로 더 크다. 연산 병목이면 처리량은
메모리 절감이 아니라 **연산 절감** 을 따라간다.

**예측하지 못한 것**: 배치를 20~28배로 늘려도 처리량이 거의 그대로다
(+0.8~2.4%). 13,704 토큰짜리 시퀀스 하나가 이미 GPU 를 포화시킨다. 배치가
사는 것은 처리량이 아니라 **동시성** 이다.

### 8.4 65% 는 벽인가 — 미실행 (B)

같은 100MB 지점에서 짧은 예산 run 이 65.0%, 긴 예산 run 이 66.9% 다(19σ).
코사인 LR 이 덜 식었기 때문이다 — **곡선이 천장에 닿은 게 아니라 LR 이
꺼지면서 멈춘 것이다.** 예산 1.43배에 +2.8%p 이고 상한이 안 보인다.

**예측**: 500MB 예산에서 71~73%. C 의 기울기 결과가 이 방향을 보강한다 —
LR 이 줄자 기울기가 다시 커졌다.

## 9. 한계

- **CPT 코퍼스가 Qwen 사전학습과 겹친다.** FineWeb-2 는 Common Crawl 이고
  Qwen2.5 도 CC 를 봤다. **C0 에 유리한 편향** 이다 — C0 의 임베딩은 그
  데이터로 이미 학습됐고 T2b 의 새 30,000행은 아니다. 격차 중 얼마가 이
  편향인지 가릴 수 없다
- **dev 가 닳았다.** 초기화도 N 도 dev 에서 골랐다. 절대값이 아니라 조건 간
  격차를 읽어야 한다
- **σ 는 17.5MB 에서 잰 하한이다.** 본 실험(168.5MB)에서는 궤적이 더 갈릴
  여지가 있다
- **seed 42 단독이다** (σ 측정 제외). 격차가 300σ 이상이라 뒤집히지 않지만
  회복률 0.5%p 같은 미세한 비교는 1회 측정끼리의 것이다
- **시스템 지표는 배치 1, RTX 5070 Ti 한 대다.** 증폭 계수는 이 GPU 의
  연산·대역폭 비율에 딸려 있다
- **학습 wall-clock 은 오염됐다** — 데스크톱이 GPU 를 함께 썼다. 처리량
  주장에 쓰지 않는다. BPB 는 영향 없다
- **능력 평가를 안 했다.** BPB 는 language modeling 이지 과제 수행이 아니다.
  "+37.8%" 가 실제 과제에서 몇 점인지 이 보고서는 답하지 못한다
- **도메인별 수치를 세분화해 인용하지 않는다** — 라벨 정확도 ~55%
