# T2a(축소) vs T2b(치환) — N 스윕

측정 2026-08-30. v1 dev 259.2MB / 63,961문서. 기준선 `qwen_original`.
run `tok_bench_sweep`, `tok_bench_sweep50k`.

T2a 와 T2b 는 각 N 에서 **같은 `prune_<N>.tsv`** 를 쓴다. 다른 것은 비운 슬롯을
그대로 두느냐(T2a) 한국어 토큰으로 채우느냐(T2b) 뿐이다.

T2b 의 한계이득이 10,000개당 22.7 → 3.8 → 1.9 → 0.9%p 로 계속 반감한다.

## 영어·코드 regression

| N | T2a 영어 | T2a 코드 | T2b 영어 | T2b 코드 |
|---:|---:|---:|---:|---:|
| 10,000 | +0.0% | +0.0% | −0.0% | −0.7% |
| 20,000 | +0.0% | +0.0% | −0.0% | −0.8% |
| 30,000 | +0.0% | +0.1% | +0.0% | −0.8% |
| 50,000 | +0.1% | **+0.8%** | +0.1% | −0.1% |

N=50,000 에서 T2a 코드가 +0.8% 로 처음 악화된다. `code_floor=100` 이 99회까지
허용하므로, 이 지점부터 코드가 실제로 쓰는 토큰을 깎기 시작한다는 신호다.

## 무엇을 사는가

T2a 가 못한 것이 아니다. **사는 물건이 다르다.**

| | 얻는 것 | 잃는 것 |
|---|---|---|
| T2a n=30,000 | embedding 26.9M 파라미터 감소 (136.1M 의 19.7%) | 압축 이득 0 |
| T2b n=30,000 | 한국어 −28.4%, 코드 −0.8% | 파라미터 감소 0 |

제거 대상이 코퍼스에서 거의 안 쓰이는 토큰이므로(3만개 제거 시 13.6억 토큰 중
0.0035%), 지우기만 해서는 토큰화가 바뀔 이유가 없다. 압축을 얻으려면 **그
자리를 채워야 한다** — 이것이 T2b 의 주장이다.

## 외부 참조와의 위치

같은 dev 에서 잰 값이다 (run `tok_bench_v1`).

| | 한국어 | 영어 | 코드 | vocab |
|---|---:|---:|---:|---:|
| HCX-SEED-0.5B | −24.9% | +0.0% | +17.6% | 110,524 |
| A.X-4.0-Light | −39.4% | +7.3% | +22.5% | 102,400 |
| **T2b n=30,000** | **−28.4%** | **+0.0%** | **−0.8%** | **151,643 (유지)** |

T2b 는 HCX 보다 한국어 압축이 좋으면서 코드 손해가 없다. A.X 는 한국어 압축이
더 크지만 코드에서 +22.5% 를 낸다. 스펙 §16 이 경고한 trade-off 를 T2b 는
치르지 않는다 — 기존 토큰을 대체하는 것이 아니라 **안 쓰이는 자리** 를 쓰기 때문이다.

## 선택: N = 30,000

50,000 이 −30.2% 로 1.8%p 더 좋지만,

- 제거 비용이 10배다 (출현 0.0035% -> 0.0364%)
- T2a 코드가 +0.8% 로 악화되기 시작한다 — 안전 여유가 줄었다는 신호
- 한계이득이 이미 반감 중이라 더 밀어도 얻는 것이 적다

CPT 는 이 하나의 N 으로만 돌린다.

## 주의

`기증 토큰 활성률` (n=30,000 에서 42.3%) 은 단독으로 해석하지 마라. dev 300문서
표본에 저빈도 기증자가 안 나온 것과, merge rank 경쟁에서 져서 발화하지 못한 것이
섞여 있다. 실제 이득은 이 표의 tok/char 이다.
