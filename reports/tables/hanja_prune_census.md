# T2a 제거분의 한자 집계

> **이 표는 코드가 적는다.** `.conda/python.exe tools/hanja_prune_census.py`
> 학습 없음, GPU 0시간. 기술 집계이며 판정하지 않는다.

등록 맥락은 [`docs/PLAN.md`](../../docs/PLAN.md) "downstream 과 한자 프로브".
간체/정자 관측은 그 등록대로 **예측 근거로만** 쓰고 결과로 인용하지 않는다.

## 제거 집합 대조

```
prune_30000.tsv 행 (탭으로 직접 읽음)      30,000
  서로 다른 token_id                       30,000
  기본 어휘(< 151,643) 밖의 id                 0
kot2a_v1_n30000/id_map.json 에서 빠진 id     30,000
  두 집합이 같은가                          예
```

**함정:** 같은 파일을 `csv` 기본 인용 해석으로 읽으면 **29,991행** 이 된다.
`token` 칸이 JSON 문자열이고 `"` 를 품은 토큰이 있어서, 여러 줄이 한 행으로
붙는다. 2026-09-29 에 이 방식으로 읽어 "9행이 모자란다" 고 잘못 보고했다.
파일도 T2a 도 30,000개가 맞다 — 틀린 것은 읽는 쪽이었다.

뜻이 없다. PLAN.md 에 손으로 적은 "상위" 목록은 정렬 기준이 기록되지 않았고,

## 한계

- `count_total` 은 `token_stats.tsv` 를 만든 코퍼스 표본의 발화 수다. PLAN.md 의
  dev 글자 중 한자 비율과는 다른 측정이다
- 한자 범위는 네 블록이다: U+3400–4DBF · U+4E00–9FFF · U+F900–FAFF ·
  U+20000–2FFFF. 강희 부수·CJK 획·기호 블록은 세지 않는다
- 한자 **포함** 은 한 글자라도 있으면 센다. 한글·영문과 섞인 토큰도 들어간다
