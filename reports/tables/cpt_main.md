# 본 CPT — 3조건 168.5MB Equal-Raw-Data

측정 2026-08-31. run `cpt_{c0_qwen,t2a_none,t2b_mean}_main_seed42`.
학습 전 지점은 같은 평가 함수·같은 2MB 예산으로 따로 쟀다
(`eval_bpb_*_main0`). 정렬 단계는 없다 — 왜 뺐는지는
[`alignment_probe.md`](alignment_probe.md).

세 조건이 **같은 원문 168.5MB** 를 본다. 문서 풀·시드·LR 스케줄이 동일하고,
다른 것은 토크나이저와 수술뿐이다.

## 압축은 됐다. 회복이 안 됐다

| 조건 | 원문 | 토큰 | tok/byte |
|---|---:|---:|---:|
| C0 | 168,505,891 | 49,922,048 | 0.296263 |
| T2a | 168,501,724 | 49,922,048 | 0.296256 |
| T2b | 168,502,276 | 34,832,384 | 0.206718 |

T2b/C0 = **0.6977**. 토큰이 30.2% 줄었고, Level 1 에서 예측한 0.696 과
소수 셋째 자리까지 맞는다. **토크나이저 수술 자체는 설계대로 작동했다.**

문제는 언어모델이다.

```
T2b 가 C0 최종까지 메워야 했던 거리   1.2428
실제로 메운 거리                      0.8132  (65.4%)
남은 거리                             0.4296
```

## T2b 도 수렴했다 — 예산을 더 준다고 될 일이 아니었다

| 지점 | 20MB | 40 | 60 | 80 | 100 | 120 | 140 | 160 | 168.5 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| C0 | 1.1484 | 1.1436 | 1.1408 | 1.1391 | 1.1382 | 1.1378 | 1.1376 | 1.1375 | 1.1375 |
| T2b | 1.7437 | 1.6472 | 1.6035 | 1.5818 | 1.5722 | 1.5687 | 1.5675 | 1.5672 | 1.5671 |

마지막 40MB 에서 T2b 는 1.5675 -> 1.5671, 움직임이 0.0004 로 자기 2 sigma
(0.002468)의 6분의 1이다. C0 도 같은 구간에서 0.00024 로 멈췄다 — **통제군이
천장에 닿았으므로 "C0 가 덜 학습돼서 이겼다" 는 반론이 성립하지 않는다.**

단서 하나: 코사인 LR 이 예산 끝에서 바닥으로 내려가므로 마지막 구간의 평탄함에는
LR 감쇠가 섞여 있다. "완전히 수렴" 보다 "이 예산·이 스케줄에서 갈 데까지 갔다"
가 정확하다. 세 조건이 같은 스케줄을 쓰므로 비교 자체는 공정하다.

## 왜 못 따라잡았나 — 노출이 희박했다

새 토큰 30,000개가 CPT 동안 몇 번 발화했는지 셌다 (20MB 표본, 168.5MB 환산).

```
새 토큰이 처리한 토큰의            43.34%
토큰당 발화  중앙값 143   평균 501   최대 45,166

  0회            3,540개  (11.8%)   <- 표본 기준이라 진짜 0 의 상한
  1~99회         8,363개  (27.9%)
  100~999회     14,814개  (49.4%)
  1,000~9,999회  3,168개  (10.6%)
  10,000회 이상    115개  ( 0.4%)
```

재현:

```
.conda/python.exe -m src.evaluation.token_exposure \
    --model artifacts/models/kot2b_v2_n30000_mean \
    --id-map artifacts/tokenizers/kot2b_v2_n30000/id_map.json \
    --pool-docs 50000 --sample-bytes 20000000 --full-bytes 168500000
```

**총량은 크지만 개별 토큰은 굶었다.** 전체 토큰의 43% 가 새 토큰인데도 그렇다 —
상위 0.4% 가 45,000번씩 나오는 동안 중앙값 토큰은 168.5MB 전체에서 143번 봤다.
896차원 벡터를 lr 1e-5 로 143번 업데이트해서 밑바닥부터 학습할 수 없다.

**초기화 문제가 아니다.** E0/E1/E2 비교에서 부품 평균이 이미 최선이었고 노름
보정은 해로웠다 ([`precpt_bpb.md`](precpt_bpb.md)). 초기화를 더 잘해도 143번으로는
못 배운다. 예산과 토큰 수의 문제다.

## 부수 관찰 — 손상된 임베딩은 다른 언어도 더 흔든다

한국어만 학습하면 영어·코드가 조금 나빠진다. C0 는 +0.22% / +0.40% 인데
T2b 는 +1.06% / +1.63% 로 4배다. 같은 데이터, 같은 스케줄인데 그렇다.
`tie_word_embeddings` 때문에 임베딩 행렬이 모든 언어의 출력 로짓 방향이고,
T2b 는 그 행렬의 30,000행이 학습 중이라 나머지가 더 밀린다.

## 한계

- **seed 42 단독이다.** 판정은 노이즈 플로어의 sigma 를 기준으로 했고, 격차가
  348 sigma 라 seed 로 뒤집힐 여지는 없다. T2a 의 영어(1.9 sigma)만 경계다
- **sigma 는 17.5MB 에서 잰 하한이다.** 실제 sigma 가 3배여도 T2a 한국어(2.4),
  코드(6.6), T2b 전부는 판정이 유지된다
- **wall_sec 은 오염됐다.** 학습 중 데스크톱 앱이 GPU 를 함께 썼고 T2a 는
  구간 처리량이 26~52 s/MB 로 2배 흔들렸다. BPB 는 영향이 없다(경합은 커널이
  언제 도는지를 바꾸지 무엇을 계산하는지는 안 바꾼다. `cudnn.benchmark` 는
  꺼져 있어 시간 기반 알고리즘 선택 경로도 닫혀 있다). **처리량 주장에 이
  컬럼을 쓰지 않는다** — 속도는 Step 7 의 통제된 `system_bench` 에서만 잰다
- **등토큰 조건은 아직 안 봤다.** 여기서는 같은 원문을 줬다. 같은 토큰수를
  주는 조건(스펙 §32~33)이 T2b 에게 더 유리하고, 그건 Phase 4 에서 잰다
- **CPT 코퍼스가 Qwen 사전학습과 겹친다** (검토 A6). FineWeb-2 한국어는 Common
  Crawl 이고 Qwen2.5 도 CC 를 봤다. 이 "continued pretraining" 은 부분적으로
  이미 본 데이터의 재학습이다. C0 통제군이 효과를 흡수하므로 **조건 간 비교는
  성립하지만**, "새 정보를 더 봤다" 가 아니라 "같은 정보를 다른 단위로 다시
  봤다" 에 가깝다. C0 가 유리한 방향의 편향이다 — C0 의 임베딩은 그 데이터로
  이미 학습된 것이고 T2b 의 새 30,000행은 아니다. 격차 0.4296 중 얼마가 이
  편향인지는 이 실험으로 가릴 수 없다
- **dev 가 닳았다** (검토 A5). E1 초기화도 N=30,000 도 dev 에서 골랐다. Final
  Test 는 잠겨 있지만 dev 기준의 선택이 누적됐으므로, 최종 수치는 dev 낙관
  편향을 포함한다. 절대값이 아니라 조건 간 격차를 읽어야 한다
