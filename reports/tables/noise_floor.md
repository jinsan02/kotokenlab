# 노이즈 플로어 — 조건별 sigma_BPB

> **이 표는 코드가 적는다.** `.conda/python.exe tools/noise_floor.py`
> 원본은 `experiments/lm_metrics.tsv` 의 final 행이다. 손으로 고치지 마라.

동일 config 를 seed 42 / 123 / 2026 으로 3회. 각 17.5MB 원문, 약 11분.

**이걸 먼저 재지 않으면 이후 어떤 비교도 해석할 수 없다.** "1.207 vs 1.198" 이
의미 있는 차이인지 판단할 근거가 없다.

seed 는 **문서 순서만** 바꾼다. 풀(5,000문서 20.0MB)을 예산(17.5MB)에 맞춰
모든 seed 가 같은 문서를 거의 다 보게 했다. 실제 비교에서는 모든 조건이
Equal-Raw-Data 로 같은 데이터를 보므로 데이터 선택 분산은 조건 간 차이의
원인이 아니다.

## 과거 표가 왜 달랐나 — 반올림에서 계산했다

2026-09-13 이전 표는 BPB 를 **소수 4자리로 반올림한 값** 에서 sigma 를 냈다
(`phase4.md` 의 T2b N=10,000 만 전체 정밀도였다). 차이는 이렇다.

| 조건 | 언어 | 전체 정밀도 | 4자리 반올림 | |
|---|---|---:|---:|---|
| C0 (원본) | 한국어 | 0.000066 | 0.000058 | 반올림 양자화 바닥 |
| C0 (원본) | 영어 | 0.000031 | 0.000058 | 반올림 양자화 바닥 |
| C0 (원본) | 코드 | 0.000054 | 0.000058 | 반올림 양자화 바닥 |

| T2a (제거만) | 영어 | 0.000016 | 0.000000 | **0 으로 나눌 뻔했다** |
| T2a (제거만) | 코드 | 0.000050 | 0.000058 | 반올림 양자화 바닥 |
| T2b (수술+E1) | 한국어 | 0.001250 | 0.001234 |  |

| T2b (수술+E1) | 코드 | 0.000050 | 0.000058 | 반올림 양자화 바닥 |
| T2b N=10,000 | 한국어 | 0.001166 | 0.001150 |  |
| T2b N=10,000 | 영어 | 0.000098 | 0.000100 |  |
| T2b N=10,000 | 코드 | 0.000059 | 0.000058 | 반올림 양자화 바닥 |

**`0.000058` 은 측정값이 아니다.** 세 값 중 둘이 같고 하나가 0.0001 다르면
반올림 sigma 는 항상 `0.0001/sqrt(3)` = **0.000058** 가 된다. 과거 표에
이 값이 반복된 것은 en/code 의 분산이 4자리 아래에 있었다는 뜻이지,
세 조건의 sigma 가 실제로 같았다는 뜻이 아니다.

## sigma 는 조건마다 다르다 — 하나로 퉁칠 수 없다

한국어에서 가장 큰 sigma 가 가장 작은 것의 **18.9배** 다.
수술로 손상된 상태(BPB 2.38)에서 출발하면 seed 에 따라 회복 궤적이
갈리기 때문이다.

**T2a 가 C0 와 비슷하다는 것이 원인을 짚어 준다.** T2a 도 30,000개를 제거하는
수술을 받았지만 sigma 가 C0 와 같은 자릿수다. sigma 를 키우는 것은
"수술을 받았는가" 가 아니라 **"수술로 손상됐는가"** 다.

## 보고 규칙

조건별 sigma 를 각각 쓴다. 두 조건을 비교할 때는 **큰 쪽 sigma** 를 기준으로
하고, `Delta > 2 sigma` 일 때만 "차이 있음", 그 미만은 "구별 불가" 로 쓴다.

> **이 규칙은 2026-08-30 에 확정됐다** — sigma 를 처음 잰 직후이자 본 CPT
> 비교(08-31) 전이다. 원래 사전 등록(08-29)은 "sigma 는 Step 5 에서 잰
> 노이즈 플로어" 라고만 적었고 조건별이라는 말이 없었다. 방향은 보수적이지만
> (큰 쪽을 쓰면 차이를 선언하기 더 어렵다) **논문에 "전부 사전 등록" 이라고
> 뭉뚱그리면 안 된다.**

### n=3 의 해상도 한계

자유도 2 다. sigma 추정 자체의 95% 신뢰구간이 이만큼 넓다.

| 조건 | 언어 | sigma | 95% CI |
|---|---|---:|---|
| C0 (원본) | 한국어 | 0.000066 | 0.000034 ~ 0.000415 |
| T2a (제거만) | 한국어 | 0.000090 | 0.000047 ~ 0.000568 |
| T2b (수술+E1) | 한국어 | 0.001250 | 0.000651 ~ 0.007855 |
| T2b N=10,000 | 한국어 | 0.001166 | 0.000607 ~ 0.007326 |

**따라서 1e-4 미만의 sigma 끼리 비교하는 것은 의미가 없다.**
en/code 에서 관측된 sigma 차이는 추정 잡음 안이다. 보고는 이렇게 한다:

```
한국어   조건별 sigma 를 그대로 쓴다. 격차가 300 sigma 이상이라 안 흔들린다
en/code  1e-4 미만 격차는 '해상도 아래' 로 보고한다. sigma 배수를 인용하지 않는다
```

## Equal-Raw-Data 가 작동한다는 증거

같은 17.5MB 예산에서 본 토큰 수 (원장 `ok` 행).

| 조건 | 원문 바이트 | 토큰 | 토큰/바이트 |
|---|---:|---:|---:|
| C0 (원본) | 17,512,264 | 5,197,824 | 0.296811 |
| T2a (제거만) | 17,511,851 | 5,197,824 | 0.296818 |
| T2b (수술+E1) | 17,521,145 | 3,629,056 | 0.207124 |
| T2b N=10,000 | 17,510,376 | 3,891,200 | 0.222223 |

T2b / C0 = **0.6978** — 예산을 바이트로 세니 압축이 좋은 조건이
**같은 원문** 을 더 적은 토큰으로 지나간다. 토큰으로 셌다면 T2b 가
43.3% 더 많은 원문을 보고도 같은 예산이라 불릴 뻔했다.

## 한계

- **예산이 17.5MB 다.** 본 실험(168.5MB)에서는 궤적이 더 갈릴 여지가 있어
  sigma 가 이보다 클 수 있다. **하한으로 다뤄라**
- **3 seed 라 sigma 추정 자체의 불확실성이 크다** (자유도 2, 위 CI 표)
- 문서 집합이 동일해 데이터 선택 분산이 빠져 있다. Equal-Raw-Data 설계에서는
  의도된 배제다
- 학습 전 BPB 는 이 표에 없다. `precpt_bpb.md` 에 있고, 노이즈 run 대부분이
  `step0` 행을 남기지 않았다
