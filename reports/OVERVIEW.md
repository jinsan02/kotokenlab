# KoTokenLab — 외부 검토용 개요

> **이 파일은 `tools/overview.py` 가 원장에서 만든다.** 서술은 코드 안에
> 문자열로 있고, 숫자는 전부 `experiments/*.tsv` 에서 읽었다. 손으로 옮긴
> 수치는 없다. 저장소를 못 보는 사람이 읽을 수 있게 자기완결적으로 쓴다.

RTX 5070 Ti 16GB **한 대** 로 돌리는 1인 프로젝트다.

## 1. 무엇을 묻는가

한국어 토크나이저를 바꾸면 무엇을 얻고 무엇을 잃는가. **어휘 크기를**
**유지한 채** 토큰을 치환하는 수술(T2b)을 걸고, 같은 코퍼스·같은 예산으로
CPT 한 뒤, 원본 토크나이저 통제군(C0)과 비교한다. 주 비교의 168.5MB는
**동일 원문량**을 맞춘 것이며, 조건별 토큰 수·update 수가 달라 동일 연산량이 아니다.

핵심 지표는 **BPB (bits per byte)** 다. token PPL은 예측 단위가 달라
토크나이저 사이에 직접 비교할 수 없다. 관계는
`log2(PPL_token) = BPB / (tokens/byte)`이고, BPB는 분모를 원문 바이트로 둔다.

회복률은 이렇게 정의한다 (`docs/RULES.md` 14b).

```
R = (B0 - Bf) / (B0 - Cf)
  B0  수술 직후 · 학습 전 한국어 dev BPB
  Bf  같은 모델을 CPT 로 예산만큼 돌린 뒤
  Cf  통제군 C0 (원본 토크나이저, 같은 코퍼스 · 예산 · 스케줄)
```

R은 기존 사전 등록을 보존하기 위한 보조 지표다. 해석은 **절대 B0/Bf/Cf와
최종 잔차 Bf-Cf를 먼저** 하고, R의 유사성만으로 불변성이나 공통 메커니즘을
말하지 않는다 (`docs/RULES.md` 14b amendment).

## 2. 실험 대상

```
백본        Qwen2.5-0.5B (tie_word_embeddings=1, 임베딩이 파라미터의 27.6%)
코퍼스      FineWeb-2 한국어 + 영어 · 코드 대조군. 문서 단위 90/5/5 분할
T2a         저빈도 토큰 30,000개 제거 (vocab 축소)
T2b         그 자리에 한국어 토큰 30,000개 치환 (**크기 유지**)
초기화      E1 = merge 부품 둘의 평균 (검증 가능한 25,821토큰에서 FVT 일치, 9절)
CPT         168.5MB 원문, bf16, gradient checkpointing, AdamW8bit
```

## 3. 1차 결과 — 교환비

### 압축 (학습 없음, dev)

| | 원본 Qwen | T2b | 차이 |
|---|---:|---:|---:|
| 한국어 tok/byte | 0.2963 | 0.2068 | **-30.2%** |
| 영어 | 0.2167 | 0.2167 | -0.0% |
| 코드 | 0.2768 | 0.2746 | -0.8% |

### 품질 (CPT 168.5MB 후, 한국어 dev BPB)

| 조건 | BPB | C0 대비 |
|---|---:|---:|
| C0 (원본 토크나이저) | 1.1375 | — |
| T2a (제거만) | 1.1368 | -0.06% |
| T2b (치환, N=30k) | 1.5671 | **+37.76%** |
| T2b (치환, N=10k) | 1.4973 | +31.62% |

수술 직후 한국어 BPB 는 2.3803 였다. 즉 CPT 가 격차의
**65.4%** 를 메웠고(N=10k 는 65.9%), 나머지는 남았다.

**압축은 설계대로 됐고 품질은 따라오지 못했다.** 그 대신 산 것은 추론
비용이다 — prefill -35~41%, KV cache -30%, 같은 문맥 창에 +44% 원문.
(시스템 수치는 `reports/tables/system_bench` 계열에 있다)

## 4. 2차 결과 — 무엇이 회복을 정하는가

1차에서 회복률이 조건을 바꿔도 65% 근처에서 겹쳤다. 2차는 그 이유를 물었고,
**사전 등록한 가설 셋 중 둘이 반증됐다.**

### R1 — 임베딩 손상 일반의 성질인가 (부정)

토크나이저를 안 바꾸고 임베딩 **행 40개만** 망가뜨린다. 손상 배율은 T2b 와
맞췄다 (학습 없는 보정으로 K 를 골랐다).

| 조건 | 학습 전 | 학습 후 | 통제군 | R |
|---|---:|---:|---:|---:|
| 행 40개 손상 (40MB) | 2.3758 | 1.4846 | 1.1464 | **72.50%** |
| T2b 치환 (40MB) | 2.3808 | 1.7539 | 1.1464 | **50.79%** |

같은 aggregate 초기 손상 배율에서 **21.71%p** 벌어진다.
그러나 행 수·노출·토큰화가 함께 달라 이 차이를 토크나이저 치환 자체에
귀속할 수 없다. **시험한 두 구성의 회복 궤적이 다르다**까지만 방어한다.

> **남은 교락:** 두 조건은 손상 배율만 같고 **행당 노출** 과 **손상 행 수** 가
> 다르다. 2026-09-19 에 시험한 손상 방식과 K<=30,000 탐색에서는 노출과
> 손상 배율을 동시에 맞추지 못했다. 다른 손상 방식까지 불가능하다는 뜻은 아니다.

### Q7 — 17.5MB에서 큰 tied 효과는 관측되지 않음

`lm_head` 를 임베딩 사본으로 복제해 tie 를 끊고(수술 전후 forward 가 비트
단위로 같은 것을 확인) 같은 실험을 돌렸다. 17.5MB × 3 seed.

```
R(untied) 42.70%   R(tied) 42.26%   차이 +0.44%p
```

paired seed 차이의 탐색적 t(df=2) 95% CI는 [+0.417, +0.471]%p다. 사전 등록한 효과 크기
바닥 ±5%p 안이지만 n=3 정규성 가정의 사후 구간이라 일반적 동등성 증명은 아니다.
forward 동일성은 시작 함수만 같다는 뜻이다. untie는 파라미터를 27.6% 늘리고
입력·출력 gradient 공유를 끊으므로 장기 학습 동역학이 같다는 결론은 아니다.

### R5 — LR 스케줄 때문인가 (긍정)

코사인 대신 **상수 LR** 로 같은 예산을 돌렸다. 감쇠만 빼고 나머지는 같다.
통제군도 상수 LR 로 다시 돌렸다 (조건이 바뀌면 대조군도 다시 잰다).

| | 코사인 | 상수 LR |
|---|---:|---:|
| T2b 한국어 BPB | 1.5671 | 1.4729 (3 seed) |
| C0 한국어 BPB | 1.1375 | 1.1274 |
| 회복률 R | 65.44% | **72.42%** |

더 직접적인 종점 잔차 `Bf-Cf`는 0.429555 -> 0.345543,
**0.084012 BPB 감소**다.

σ_R = 0.026%p (3 seed). 등록 예측은 "71~75%" 였고 경쟁 등록
("68.5% 이하")은 기각됐다.

**헤드라인이 바뀐다.** 168.5MB의 코사인 종점은 회복 한계가 아니었다.
상수 LR이 그 유한 예산 종점을 개선했고 C0도 좋아졌다. 무한 예산 점근선이나
일반적인 "벽"은 이 실험으로 식별하지 않았다.

## 5. 한자 프로브 (D1~D3)

T2a 가 제거한 30,000개 중 13,310개(44.4%)가 한자 포함 토큰이었다. 빈도
필터의 부수 효과이고, 절단면은 **간체 전용자** 쪽으로 치우쳐 정자(國 無 韓)는
남았다. 한자가 밀집한 부분집합(787문서)과 KMMLU 로 확인했다.

| | C0 | T2a | T2b |
|---|---:|---:|---:|
| 한자 밀집 BPB | 1.2607 | 1.2610 | 1.6734 |
| KMMLU 정확도 (1,900문항) | 0.3153 | 0.3132 | 0.2368 |

T2a 는 BPB +0.03%, KMMLU -0.21%p 로 **C0 와 구별되지 않는다**
(등록 경계 ±2%p, paired bootstrap). 다만 C0 가 찍기(25%)보다 약
6.5%p 위라 **감도가 낮은 계기** 다.

## 6. 3차 설계 — 2026-09-19 외부 검토 amendment

```
우선  학습 회계·BPB 위치 대응·split/중복 감사를 닫고 N=30k C0/T2b 대응 seed
수정  동일 update/토큰 예산 비교와 신규 행 warm-start 대조군
수정  WSD — cooldown 20%도 총 168.5MB 예산 안의 비용으로 센다
후순위 500MB — 유한 구간 곡선 연장으로만 보고, 점근선 판정은 하지 않는다
후순위 KMMLU 39과목 · 1.5B — 핵심 재현과 compute 대조 뒤
취소  R 유사성 기전 검정(P3-C), CPT 행 이식을 완벽한 초기화 상한으로 읽는 P3-E
```

## 7. 방법론에서 지키는 것

- **사전 등록.** 예측 · 판정 경계 · 효과 크기 바닥을 돌리기 전에 커밋한다.
  결과를 보고 경계를 옮기지 않고, 옮겨야 하면 그 사실을 날짜와 함께 적는다
- **효과 크기 바닥 5%p + 2σ.** 2σ는 seed SD 기반 등록 휴리스틱이지 95% CI가 아니다
- **조건이 바뀌면 통제군도 같은 조건에서 다시 잰다** (R5 의 상수 LR C0)
- **결과는 코드가 원장에 쓴다.** 마크다운에 손으로 옮기지 않는다
- **append-only 원장** — 실패한 run 도 지우지 않는다 (fail · abort 포함)
- 커밋 훅이 규칙을 집행한다 — 결과 커밋에 코드가 섞이면 거부된다

## 8. 알려진 한계 (전부 문서에 적혀 있다)

- **0.5B 한 모델.** 1.5B 는 수술 손상만 쟀고 CPT 회복력은 미측정
- **seed 42 단독** 인 run 이 많다 (노이즈 플로어와 R5 만 3 seed)
- **dev 가 닳았다.** 초기화도 N 도 dev 에서 골랐다. Final Test 는 한 번도
  열지 않았다
- **CPT 코퍼스와 Qwen 사전학습은 모두 Common Crawl 계열일 수 있다.** 실제
  중복률과 편향 방향은 측정하지 않아 알 수 없다
- **평가 문항 오염 제거가 구현되지 않았다.** 2026-09-19 에 따로 세어 보니
  KMMLU 6과목 중 덮임 50% 이상은 2문항이었다 (상용구 겹침이 대부분)
- **도메인 라벨 정확도가 ~55%** 라 도메인별 수치를 인용하지 않는다
- **ZeTT 를 못 돌렸다.** CPT 행 이식은 몸통-행 상호적응을 깨는 compatibility
  진단일 뿐, 완벽한 초기화 상한이나 ZeTT 대체 baseline이 아니다
- 학습 wall-clock 이 오염됐다 (데스크톱이 GPU 를 함께 썼다). 속도 주장에
  쓰지 않는다. BPB 는 영향 없다

## 9. 초기화 baseline 의 위치

E1(merge 부품 평균)은 **검증된 범위에서만 FVT와 같다** — standalone
재토큰화가 정의되는 25,821개에서 100% 일치했다. 나머지 4,179개(13.9%)는 표면형이 유효
UTF-8 이 아니라 FVT 를 적용할 수 없는 경우이고, 거기서는 merge 계보로
확장한다. 그 확장분이 바이트 단위 평균과 얼마나 다른지도 쟀다 (중앙값 코사인
0.520 으로, FVT 가 정의되는 구간의 0.171 보다 오히려 가깝다).

E2(역빈도 가중)는 **FOCUS 가 아니다** — 가중치 출처가 유사도가 아니라 빈도다.

선행 연구에는 continued-BPE, leaf pruning, 평균 subtoken 초기화, embedding-only
warm-start, 저예산 tokenizer swapping이 이미 있다. 따라서 novelty는 개별 기법이
아니라 **한국어 소형 모델·고정 vocabulary 크기·제한 CPT에서의 회복 곡선과
비용-품질 trade-off를 통제축별로 측정한 증거**로 한정한다.

## 10. 운영 환경 — 장비 한 대를 원격으로 돌린다

실험은 **데스크톱 워크스테이션 한 대** (RTX 5070 Ti 16GB) 에서만 돈다.
클러스터도 클라우드도 없고, 학습을 두 개 동시에 띄우지 않는다 — 그래서
일정표의 시간이 곧 실제 대기 시간이다.

긴 run(3~11시간)을 책상 앞에서 지킬 수 없으므로 **원격 접속** 을 붙여 뒀다.

```
사설 메시 VPN (Tailscale)   기기끼리만 닿는 사설망. 포트를 공개하지 않는다
OpenSSH 서버               그 망 안에서만 접속. 자동 시작 서비스
쓰임                       run 시작 · 진행 확인 · 원장 tail · 중단
```

**기기 이름 · 주소 · 키 · 계정 정보는 저장소에 넣지 않는다.** 저장소는 공개를
전제로 쓰고 있고, 접속 정보는 실험의 재현성과 무관하다. 재현에 필요한 것은
`env/ENV_SNAPSHOT.tsv`(드라이버 · 라이브러리 버전 해시)와 원장이다.

한 대뿐이라는 제약이 설계를 여러 번 바꿨다 — 7B 를 포기하고 0.5B 에서 깊게
판 것, 비교 실험을 40MB 로 줄인 것, Q7 게이트에서 6시간짜리 본편을 취소한 것이
전부 여기서 나온다.
