# SPEC P2 — 손상된 임베딩의 회복 한계

> **설계 문서. 아직 아무것도 돌리지 않았다.**
> 1차는 `p1-closed` 태그로 닫혔다 — 결과는
> [`../reports/FINAL_REPORT.md`](../reports/FINAL_REPORT.md).
> 규칙은 그대로 [`RULES.md`](RULES.md) 를 따른다. 이 문서는 범위와 사전 등록만 담는다.

## 0. 왜 이것인가

1차의 가장 놀라운 결과는 토크나이저 얘기가 아니었다.

```
예산     N=30k(168MB)  N=30k 등토큰(241MB)  N=10k(168MB)
 20MB       51.2%          50.9%             51.5%
 40MB       59.0%          59.1%             59.4%
 80MB       64.3%          65.6%             64.7%
```

손상 크기도(2.3803 vs 2.1918) 노출도(중앙값 143회 vs 623회) 다른데
**회복률이 1%p 안에서 겹친다.** 그리고 아무도 왜인지 모른다.

우리는 "토큰을 치환했더니" 라는 경로로 여기 왔지만, 실제로 일어난 일은
**임베딩 행 K개가 망가진 상태에서 CPT를 했다** 이다. 토크나이저는 손상을
만드는 한 가지 방법일 뿐이다.

**토크나이저를 아예 안 건드리고 임베딩 행만 망가뜨려도 65%가 나온다면**,
그것은 한국어 토크나이저의 성질이 아니라 tied-embedding 언어모델의 일반
성질이다. 훨씬 넓고 훨씬 검증 가능하다.

이 틀에서 **1차는 실패한 프로젝트가 아니라 65% 법칙을 발견한 파일럿** 이 된다.

## 1. 사전 등록 질문

**돌리기 전에 고정한다.** 판정은 1차와 같다 — `개선 / 구별 불가 / 악화`,
경계는 2σ. 유리한 쪽으로 반올림하지 않는다.

| # | 질문 | 예측 | 예산 |
|---|---|---|---|
| **R1** | 토크나이저를 안 바꾸고 임베딩 행만 망가뜨려도 65%가 나오는가 | **나온다.** 법칙은 임베딩의 성질이다 | 40MB × 2 |
| **R2** | 손상 **종류**(무작위 · 부품평균 · 순열)에 따라 다른가 | 초기 손상 크기는 다르지만 **회복률은 같다** | 40MB × 3 |
| **R3** | 손상 **규모** K(1k / 10k / 30k / 100k)에 따라 다른가 | 같다. 1차가 10k·30k 에서 이미 보였다 | 40MB × 4 |
| **R4** | **tie 를 끊으면 달라지는가** | **회복률이 오른다.** 입력 표현과 출력 방향을 따로 고칠 수 있으므로 | 168.5MB × 2 |
| **R5** | **상수 LR 이면 65% 를 넘는가** | **넘는다. 71~75%** | 168.5MB × 2 |

### R1 이 전제다

R1 에서 65% 가 **안 나오면 거기서 멈춘다.** 그러면 이 현상은 토크나이저 치환에
특유한 것이고, 결론을 그렇게 좁혀서 1차 보고서에 덧붙이면 된다. **그것도 답이다.**

R2·R3 은 R1 이 성립할 때만 의미가 있다 — 법칙의 경계를 재는 실험이기 때문이다.

### R4 가 본안이다

1차에서 반증한 가설 셋이 **전부 `tie_word_embeddings` 를 가리켰다.**

- 노름 보정이 해로웠다 — 키우면 학습 안 된 토큰을 더 자신 있게 예측한다
- 정렬이 실패했다 — 한국어 행만 움직이는 lr 이 없다
- 65% 벽의 유력 후보 — 한 벡터가 표현과 출력 방향을 동시에 해내야 한다

**그런데 한 번도 직접 검증하지 않았다.** tie 를 끊고 같은 실험을 돌리면 갈린다.

### R5 는 1차가 남긴 방증 둘을 닫는다

같은 100MB 지점에서 짧은 예산 run 이 65.0%, 긴 예산 run 이 66.9% 였다(19σ).
그리고 80MB → 100MB 에서 임베딩 기울기가 오히려 올랐다(3.05 → 3.39) — 같은
구간에서 lr 이 6.0e-06 → 4.3e-06 으로 떨어졌다. 업데이트는 `lr × grad` 이므로
**LR 이 회복을 끊고 있다는 방증** 이다. 상수 LR 로 돌리면 닫힌다.

## 2. 하드웨어가 정하는 범위

RTX 5070 Ti 16GB 한 대. 1차 실측(0.5B CPT 11,382MB)을 뜯어 1.5B 를 추정하면:

| 항목 | 0.5B | 1.5B 추정 |
|---|---:|---:|
| 가중치 bf16 | 988MB | 3,088MB |
| 기울기 bf16 | 988MB | 3,088MB |
| AdamW8bit 상태 | 988MB | 3,088MB |
| 로짓 (bs2 × 2048 × 151,936) | ~2,489MB | 같음 |
| 활성화 (gradient checkpointing) | ~5,402MB | ~9,886MB |
| **합계** | **11,382MB** | **~21,639MB** |

**1.5B 전면 CPT 는 같은 조건으로 안 들어간다.** `micro_bs 1` 로 낮추면
약 15,451MB 로 경계선이고, `seq 1024` 까지 낮추면 들어가지만 **0.5B 와 다른
학습 조건** 이 되어 비교가 깨진다.

**이 숫자는 추정이다. 1일차에 VRAM 탐침으로 실측한다** — 1차에서 계산 없이
어림했다가 4배 틀린 적이 있다.

| 대상 | 현 사양 | 판단 |
|---|---|---|
| 0.5B 전면 CPT (R1~R5 전부) | **됨** | 11.4GB. tie 를 끊어도 +0.8GB 로 12.2GB |
| 1.5B Pre-CPT 손상 (K 스윕) | **됨** | 7.1GB. R3 를 1.5B 에서도 확인 |
| 1.5B 추론 시스템 지표 | **됨** | Q6 를 스케일로 확장 |
| 1.5B 전면 CPT | **경계선** | `micro_bs 1` 탐침 먼저. 안 되면 서버 대기 |
| 7B 무엇이든 | **안 됨** | 아래 참조 |

### 7B 를 서두르지 않는 이유

`experiments/models.tsv` 실측:

```
Qwen2.5-0.5B   tie=1   임베딩 27.6%   ← 1차를 여기서 했다
Qwen2.5-1.5B   tie=1   임베딩 15.1%   ← 손상까지 확인했다
──────────────────────────────────────  구조가 바뀌는 선
A.X-4.0-Light  tie=0   임베딩  5.1%
A.X-4.0        tie=0   임베딩  1.2%
```

**7B 급은 tie 가 끊겨 있다.** 그러니 7B 로 바로 가면 스케일과 tie 를 동시에
바꾸는 셈이고, 차이가 나와도 **원인을 영영 가릴 수 없다.** R4 를 0.5B 에서
먼저 풀어야 7B 의 결과를 읽을 수 있다.

1차에서 정렬 실험이 `freeze` 와 `lr` 을 한꺼번에 바꿨다가 겪은 함정과 같다.

## 4. 예산을 줄이는 두 결정 (사전에 못 박는다)

### 4.1 비교 실험은 40MB 로 한다

1차 데이터가 허락한다 — 40MB 지점에서 세 조건의 회복률이 59.0 / 59.1 / 59.4%
로 **이미 갈렸다** (최종 65% 의 90% 지점). 조건 **비교** 에는 40MB 면 충분하다.

최종값이 필요한 R4·R5 만 168.5MB 로 간다. 이 하나로 예산이 4배 줄어든다.

**결과를 보고 바꾸지 않는다.** 40MB 에서 조건이 안 갈리면 그것 자체가 보고할
사실이고, 예산을 늘려 갈릴 때까지 돌리지 않는다.

### 4.2 손상 조건의 sigma 는 보수적 상한을 쓴다

조건이 10개가 넘는데 조건마다 σ 를 재면(17.5MB × 3 seed ≈ 35분) 6시간이다.

1차가 근거를 준다 — 손상된 조건의 σ 가 **0.001234**(N=30k)와 **0.001166**(N=10k)
으로 거의 같았다. 손상 정도가 3배 달라도 σ 는 6% 차이다.

**σ = 0.0013 을 모든 손상 조건의 상한으로 쓰고, 헤드라인 비교(R4·R5)만
실측한다.** 큰 σ 는 차이를 **덜** 검출하는 쪽으로만 틀리므로 안전하다.
안 잰 조건에서 2σ 안에 들면 규칙대로 "구별 불가" 다.

## 5. 1차에서 물려받지 **않을** 것

과정 결함이다. 규약으로 못 박고 시작한다.

| | 1차에서 무슨 일이 있었나 | P2 규약 |
|---|---|---|
| **어림 금지** | Phase 5 를 "약 2시간" 이라 했는데 32분이었다. 지점당 실측이 이미 있었는데 계산을 안 했다 | 데이터가 있으면 **계산한다.** 없을 때만 어림하고 그렇다고 말한다 |
| **계측기 먼저** | `grad_norm_emb` 컬럼을 만들어 두고 마지막 날에야 켰다. 진단 스크립트도 스크래치패드에 있었다 | **1일차에 전부 켠다.** 인용할 숫자를 내는 코드는 저장소 안에 있다 |
| **σ 는 실제 예산에서** | 17.5MB 에서 재고 168.5MB 에 썼다. 하한인 줄 알면서 썼다 | 헤드라인 σ 는 **그 실험의 예산에서** 잰다 |
| **헤드라인은 3시드** | 주 결과가 시드 1개였다. 회복률 0.5%p 비교를 1회 측정끼리 했다 | R4·R5 의 최종값은 **42/123/2026** |
| **널 대조군 먼저** | Q6 에서 처음 했고 효과가 컸다 — 계측기 바닥이 0.1~0.5% 임을 알려줬다 | 새 계측기는 **차이가 나면 안 되는 자리** 부터 잰다 |

## 6. 물려받는 것

인프라는 그대로 쓴다. 1차에서 나흘 걸린 준비가 0일이다.

- 원장 · 훅 · CI · `RunContext` · 스키마
- BPB 평가 (`src/evaluation/bpb.py`), 회복률 지표 정의
- 노이즈 플로어 규약, 조건별 σ 원칙
- `tools/watch_run.py` 감시, `token_exposure` 진단
- 0.5B 기준선 전부 — C0 1.1375, 조건별 σ, 회복 곡선 3개

## 7. 이 설계가 답하지 **못하는** 것

- **왜 65% 인가** 가 아니라 **무엇이 그 값을 정하는가** 를 묻는다. R4·R5 가
  둘 다 예측대로 나와도 "tie 와 LR 이 관여한다" 까지이고, 기전의 수식은 없다
- **7B 이상** 은 못 만진다. R4 의 답이 나온 뒤 서버가 생겼을 때의 일이다
- **능력 평가** 는 여전히 없다. BPB 는 language modeling 이지 과제 수행이 아니다
- 1차의 코퍼스 편향(`host_cap` 15.79%)을 그대로 물려받는다. 두 번째 코퍼스로
  재현하지 않는 한 그 축은 열려 있다

## 8. 종료 조건

R1~R5 에 답이 붙으면 끝난다. **R1 이 부정이면 거기서 끝난다** — 그 경우
결론은 "65% 법칙은 토크나이저 치환에 특유하다" 이고, 1차 보고서에 한 절로
덧붙인다.

1차와 같다: **부정 결과도 완성이다.** 사후에 지표를 바꿔 "개선" 을 만들지 않는다
([RULES.md](RULES.md) 14번).
