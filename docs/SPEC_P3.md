## 0. P2 가 남긴 것

P2 는 "65% 회복 정체는 무엇 때문인가" 를 물었고 세 답을 얻었다.

```
R1  임베딩 복구 일반의 성질이 아니다 — 행 40개 손상은 72.50%, 치환은 50.79%   부정
Q7  tie 때문이 아니다 — untie 해도 +0.44%p                                    부정
R5  LR 스케줄 때문이다 — 상수 LR 에서 72.42%                                  긍정
```

한자 프로브(D1~D3)는 T2a 의 한자 토큰 제거가 흔적을 남기지 않았다고 답했다.

그래서 **"65% 벽" 은 헤드라인이 될 수 없다.** 코사인 스케줄의 산물이었다.
P3 는 그 자리에서 이어지는 질문 넷과 처방 하나를 묻는다.

```
포화      상수 LR 에서도 결국 멈추는가                    P3-A
불변성    "조건이 달라도 R 이 같다" 도 스케줄의 산물인가    P3-C
격차      R1 의 21.7%p 는 어디서 오는가                   P3-D · P3-E
비용      BPB 격차가 과제 점수로 얼마인가                  P3-F
처방      어휘 교체 CPT 에 어떤 스케줄을 쓸 것인가          P3-B
```

시간 계산의 근거 (원장 `wall_sec`):

```
T2b 상수 168.5MB   4,317~4,385초      C0 상수 168.5MB   5,823초
T2b10k 코사인 168.5MB  4,051초         손상 K=40 40MB   2,381초
T2b 40MB (r1base)  1,893초            D3 KMMLU 1,900문항  약 190초/모델
```

500MB 는 168.5MB 실측에 예산 비를 곱했다 — 평가 간격(20MB)이 같으므로 평가 횟수도
같은 비율로 는다. **어림이 아니라 계산이지만 선형 가정이다.** 첫 20MB 속도로 검산한다.

F 의 문항 수는 **받기 전에는 모른다.** 39과목 test 파일의 바이트(Hub 메타데이터)를
6과목의 바이트당 문항 수로 나눈 추정이며, 받은 뒤 코드가 센다.

### A — 상수 LR 포화, R5 재현을 내장한다

R5 는 168.5MB 에서 끝났고 곡선은 아직 내려가고 있었다. 500MB 로 늘리면서
**168.5MB 까지는 R5 와 같은 run** 이 되도록 만든다. 그러면 한 run 이 재현과 확장을
동시에 한다.

지금 코드로는 그렇게 되지 않는다 — 원인이 둘이다 (§3).

### B — WSD

실무에서 가장 쓸모 있는 결과는 "어휘를 바꾼 뒤 CPT 에는 코사인을 쓰지 마라" 다.
상수 LR 은 회복률은 높지만 끝까지 LR 이 높아 감쇠에서 얻는 이득이 없다.
WSD(워밍업 · 상수 · 끝에서 감쇠)는 두 쪽을 합치려는 스케줄이다. **1차 지표를 회복률이 아니라 T2b 의 절대 BPB 로
잡는다** — WSD 는 C0 도 좋게 만들어 회복률이 오히려 내려갈 수 있고, 실무자가
원하는 것은 절대 품질이다.

### C — 불변성

P2 의 출발점은 "N · 예산 · 등토큰이 달라도 회복률이 1%p 안에서 겹친다" 였다.
R5 는 정체가 스케줄의 산물임을 보였는데, **불변성도 그런지는 모른다.** 가장 싼
조건 하나(T2b10k)로 묻는다.

### D — 격차 분해

R1 의 두 조건은 손상 배율만 같고 셋이 다르다. 기존 어휘를 망가뜨리는 방법으로는
**토큰화 변경** 을 고정한 채 나머지 둘을 옮길 수 있다. 다만 드문 행은 손상에
기여가 작아서, 노출을 맞추면 손상 배율을 못 맞출 가능성이 크다. 그래서 D0 가
게이트다 — 학습 없이 몇 분이면 안다.

permute(D1)는 R2 에서 살아남는 유일한 조건이다. 행 · 노출 · 토큰화를 R1 과 같게 두고
**손상의 종류만** 바꾼다.

### E — 오라클 초기화

ZeTT 를 못 돌리는 대신, **초기화를 이보다 잘할 수는 없는 값** 을 넣어 본다. CPT 를
마친 T2b 의 새 행이다. 이것으로도 격차가 절반 이상 남으면, 더 좋은 초기화 연구는
이 설정에서 이득이 제한적이라는 근거가 된다.

### F — 과제 비용

D3 에서 T2b 가 C0 보다 낮게 나왔지만 등록 비교가 아니었고, 그 6과목은 이미 봤다.
**본 데이터로 등록하지 않는다.** 나머지 39과목만 쓴다. 상수 LR 체크포인트는
R5 가 저장하지 않았으므로 A 의 168.5MB 저장본을 쓴다 — A 가 R5 를 재현하도록
설계한 이유가 하나 더 있는 셈이다.

### G — 1.5B

P2 SPEC §2 의 추정은 `micro_bs 1` 에서 약 15.5GB 로 경계선이었다. 탐침은 몇 분이다.
Q7 이 tie 를 원인에서 뺐으므로, 1.5B 가 들어가면 "구조가 달라서 비교할 수 없다" 는
장벽 하나가 줄어든다. **그래도 0.5B · 1.5B 두 점 밖으로 외삽하지 않는다.**

## 4. 이 설계가 답하지 못하는 것

- A 가 "감속이 이어진다" 여도 **무한 예산의 값** 은 여전히 말하지 못할 수 있다
- D2 는 노출과 손상 행 수를 **함께** 옮긴다. 둘을 서로 가르지 못한다
- E 의 이식 행은 다른 몸통과 함께 학습됐다. "완벽한 초기화" 의 근사다
- F 는 0.5B 의 KMMLU 라 감도가 낮다 (D3 의 C0 가 찍기보다 약 6.5%p 위)
- KMMLU 가 Qwen 사전학습에 들어갔는지는 알 수 없다. W0-12 는 **우리 CPT 풀** 만 본다
- 백본이 tied 다. untied 와의 차이는 Q7 이 17.5MB 에서 쟀을 뿐이다 (§5)
- seed 는 A · C · D · E 가 1개다. R5 의 sigma_R 이 0.026%p 로 작아서 택한 절충이며,
  판정 경계 근처에 떨어지면 seed 를 늘리지 않고 **경계 근처였다고 보고한다**

## 5. 외부 연구가 부르는 세 요구 — 2026-09-19 판단

세 편을 읽고 나온 요구를 여기서 처리한다. 셋 다 **P3 의 run 을 늘리지 않는다.**

### (1) HanjaBridge 의 `k=0` 대조군 — 이미 있다

그 논문은 "한자 없이 CPT + 증류만" 을 대조군으로 두어 향상의 절반만 한자
덕분임을 스스로 보였다. 우리 쪽 대응물은 **`cpt_c0_qwen_main_seed42`** 다.

```
원본 토크나이저 · 치환 없음 · 같은 코퍼스 · 같은 예산 168.5MB · 같은 코사인 스케줄
```

게다가 이것은 곁다리가 아니라 **회복률의 분모** 다 ([RULES 14b](RULES.md)) —
`R` 의 정의 자체가 "치환 없이 같은 예산으로 CPT 만 한 모델" 을 기준선으로 둔다.
R5 에서는 상수 LR 용 대조군(`cpt_c0_qwen_r5_seed42`)도 따로 돌렸다.
**리뷰어의 첫 질문은 이미 닫혀 있다.** 논문에서 이 사실을 표 옆에 명시한다.

### (2) EEVE 의 untied 대조군 — (b) 한계로 남긴다. 다만 근거가 있다

EEVE 는 SOLAR-10.7B(untied)이고 우리는 Qwen2.5-0.5B(tied)라, T2b 결과가
스케일 때문인지 tying 때문인지 이 실험만으로는 못 가린다 — 맞는 지적이다.

**그런데 이 축은 P2 에서 직접 쟀다.** Q7 이 0.5B 를 untie 해서 같은 실험을 돌렸고
(S1 에서 forward 가 비트 단위로 같은 것까지 확인), 결과는 `ΔR = +0.44%p` 로
효과 크기 바닥 5%p 의 1/11 이었다 (record `36c8b5f`).

```
(a) untied 소형 대조군을 168.5MB 로 다시    1 seed 쌍 약 3.5h · 헤드라인 3 seed 면 8~10h
    (원장 실측 기준: T2b 34.8M · C0 49.9M 토큰, untied 는 lm_head 만큼 느리다)
(b) 한계로 명시하고 Q7 의 17.5MB 결과를 근거로 단다     0h
```

**(b) 를 고른다.** (a) 는 Q7 게이트가 이미 "구별 불가" 를 낸 질문에 6~10시간을
더 쓰는 것이고, P2 가 **결과를 보고 S4 를 취소한 결정** 을 되돌리는 셈이 된다.
대신 한계 문장을 이렇게 쓴다.

> 우리 백본은 tied 이고 EEVE 의 것은 untied 다. 스케일과 tying 이 함께 다르므로
> 두 결과를 직접 비교하지 않는다. 다만 **같은 백본을 untie 해서 재본 결과**
> (17.5MB × 3 seed)에서는 회복률 차이가 +0.44%p 로 우리 효과 크기 바닥(5%p)에
> 한참 못 미쳤다. tying 이 이 현상의 원인일 가능성은 그만큼 낮다.

바꿀 조건: **P3-A 가 "감속이 없다"(멱법칙) 로 나오면** untied 에서도 같은 모양인지가
새 질문이 된다. 그때 다시 꺼낸다.

### (3) ALM 자기증류 (`src/surgery/distillation.py`) — 견적만 낸다

teacher = 수술 전 원본 Qwen2.5-0.5B, student = T2b 수술 모델. CPT 의 loss 를
ALM(arXiv 2503.20083)의 chunk-level likelihood matching 으로 바꾸는 경로다.
**초기화가 아니라 목적함수 교체** 라는 점이 핵심이고, 그래서 P3-E(오라클 초기화)와
겹치지 않는다.

**연산 비용** — 원장 실측에서 계산한다.

```
같은 168.5MB 에서   T2b(student)  34.8M 토큰       C0 토크나이저(teacher)  49.9M 토큰
학습 1스텝의 구성    forward 1 + gradient checkpointing 재계산 1 + backward 2  = 4 단위
teacher 추가         forward 1 단위 x (49.9 / 34.8) = 1.43 단위, grad 없음
-> 증가율            1.43 / 4 = +36%
-> 168.5MB 1조건     4,344초 -> 약 5,900초 (1.6h)
```

**VRAM** — teacher 가중치 bf16 988MB 가 얹힌다. 현재 peak allocated 11,382MB 에
더하면 약 12.4GB 이고, Q7 untied(12,167MB)가 들어갔으므로 16GB 안에 든다. 다만
여유가 얇아 **`micro_bs 1 / accum 16` 대비책** 을 같이 등록해야 한다.

**진짜 비용은 연산이 아니라 정렬이다.** teacher 와 student 의 토크나이저가 달라
chunk 경계가 안 맞는다. 우리 `pack()` 이 조각마다 **정확한 원문 바이트** 를 들고
있으므로(1차에서 Equal-Raw-Data 를 지키려고 만든 것) 같은 바이트 구간으로 teacher
조각을 만들 수 있다 — 설계는 있으나 구현·테스트가 **약 하루** 다.

**판단: P3 에 넣지 않는다.** 이유는 셋이다.

- P3 의 남은 질문(포화 · 불변성 · 처방)은 **목적함수를 바꾸지 않은 축** 에서
  답해야 한다. 증류를 섞으면 R5 · P3-A 와 나란히 못 놓는다
- 사전 등록을 새로 써야 한다 (예측 · 판정 경계 · 실패 조건)
- 마감(11-06)까지 P3 W0~W3 가 먼저다

**P3 가 끝난 뒤의 1순위 후보로 둔다.** 그때 등록할 것: teacher 고정 여부,
chunk 정렬 규칙, KL 온도, 그리고 **"증류가 없으면 얼마인가" 대조군**(= 지금의 T2b).
