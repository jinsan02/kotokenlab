### W0-1 — sigma 재계산 (완료 2026-09-13)

`noise_floor.md` 의 sigma 는 BPB 를 소수 4자리로 반올림한 값에서 계산됐고,
`phase4.md` 의 T2b10k 만 전체 정밀도다. 두 표가 다른 규칙을 쓴다.

```
조건·언어      보고값      전체 정밀도
C0 ko         0.000058    0.000066
T2a ko        0.000100    0.000090
T2b30k ko     0.001234    0.001250
C0 en         0.000058    0.000031
T2a en        0.000000    0.000016     <- 0 으로 나눌 뻔했다
```

따라오는 것:

- **"21배" -> 18.9배**, **"348 sigma" -> 343.7 sigma** (T2b 판정은 유지)
- **판정 하나가 뒤집힌다** — T2a 영어. 보고는 1.9 sigma "구별 불가", 전체
  정밀도면 3.6 sigma "악화". `cpt_main.md` 가 *"T2a 의 영어만 경계다"* 라고
  이미 짚어 둔 자리다
- **en/code 의 `0.000058` 은 측정값이 아니라 반올림 양자화 바닥이다**
  (0.0001/sqrt(3) = 0.0000577). 그래서 표에 같은 값이 반복된다

한 것:

```
tools/noise_floor.py    전 조건 x 전 언어, 전체 정밀도. 표를 코드가 쓴다
tools/verdicts.py       판정도 손계산이었다 — 같은 결함이라 같이 닫았다
```

**판정에도 두 번째 잣대를 붙였다.** 판정은 seed 42 한 번의 관측을 n=3 에서
추정한 sigma 와 비교한다. 새 관측 하나에 대한 95% 예측구간은 `2 sigma` 가
아니라 `t(0.975,2) x sqrt(1+1/3) = 4.97 sigma` 로 **2.5배 넓다.**
사전 등록 규칙은 그대로 두고(RULES 14), 예측구간을 못 넘는 칸에 표시를 단다.

걸린 칸은 **T2a 영어 하나** 다 (3.6 sigma). 사전 등록 규칙으로는 "악화" 지만
예측구간을 못 넘으므로 **"이 설계로는 분해되지 않음" 으로 보고한다.**

그리고 **n=3 의 한계를 같이 적는다.** 자유도 2 면 sigma 추정의 95% CI 가
대략 `[0.52 sigma, 6.3 sigma]` 다. 0.000031 과 0.000058 을 가르는 것은 의미가
없다. 보고 규칙을 이렇게 바꾼다:

> en/code 의 sigma 는 3 seed 로 분해되지 않는다. **1e-4 미만 격차는
> "해상도 아래" 로 보고한다.** 한국어 판정(348 / 308 / 320 sigma)은 어느
> sigma 를 쓰든 흔들리지 않는다.

커밋은 `fix(eval)` + `Invalidates:` 다. 무효화되는 것은 판정 문장이지 run 이
아니므로 trailer 에 그 사실을 적는다.

### W0-2 — 정체 자명성 논증 (완료)

[`plateau_nulls.md`](../reports/tables/plateau_nulls.md) ·
`tools/plateau_nulls.py`. 학습 없음, 원장만 읽는다.

헤드라인에 대한 가장 강한 반론은 실험이 아니라 한 문장이었다 —
*"고정 예산 최적화가 남은 격차의 일정 비율을 메우는 건 수렴이 원래 그렇지 않나?"*

맞는 지적이다. 1차 완화 `dL/dD = -k(L-L*)` 를 풀면 `R = 1-e^(-kD)` 이고
**이 R 은 초기 손상과 무관하다.** 귀무모형이 이미 "조건이 달라도 R 은 같다" 를
예측한다. 반박 못 하면 헤드라인이 통째로 없어진다.

```
N1  유효 k 가 상수여야 한다        ->  422배 떨어진다            기각
N2  LR 로 정규화하면 상수여야 한다  ->  31배 남는다 (lr 은 9.2배)  기각
N3  지수모형의 등토큰 예측          ->  78.2% 예측, 실측 68.2%    9.9%p 과예측
```

**N2 가 핵심이다.** N1 이 깨지는 건 코사인 LR 이 0 으로 가니 당연할 수 있다.
LR 로 나누고도 31배가 남으므로 **감속의 대부분은 스케줄이 아니다.**

**하지 않는 주장**: 점근선. `L = L_inf + A*D^-alpha` 적합이 식별되지 않는다 —
예산 범위가 0.92 decade 뿐이라 잔차가 `L_inf` 에 단조고 내부 최소가 없다.
"무한 예산에서 몇 %에서 멈춘다" 는 이 데이터로 못 한다.

이 분석은 **사후** 다. 논문에서 exploratory 로 표시하고, 확증은 W0-3 의
등록 B 에서만 주장한다.

### W0-5 — 초기화 baseline 명명

| 우리 것 | 선행 | 판정 |
|---|---|---|
| **E1 부품 평균** | **FVT** (Gee et al., 2022) | **거의 같다. 동일하지는 않다** |
| E2 역빈도 가중 | FOCUS | **다르다** |

- **FVT** 는 새 토큰의 표면형을 원 토크나이저로 **다시 토큰화**해 나온 조각들의
  평균이다. E1 은 `id_map.json` 의 merge 부품 둘을 쓴다. T2b 는 새 토큰 =
  merge 1개라 보통 일치하지만 **구성상 보장되지 않는다** — BPE 가 그 문자열을
  다르게 쪼갤 수 있다. `init_mean.py` docstring 이 *"다시 토큰화해서 알아내야
  하는 불확실성이 없다"* 고 적어 둔 그 지점이다
  - **할 일**: 새 토큰 30,000개를 base 토크나이저로 재토큰화해 `[left, right]`
    와 일치하는 비율을 센다. GPU 0시간
  - 표기: **"FVT 와 동등하되 분해를 재토큰화가 아니라 merge 계보에서 취한다"**
    + 불일치율 각주
- **FOCUS** 는 겹치는 어휘에 대해 보조 임베딩(fasttext) 유사도로 희소 볼록결합을
  만든다. E2 는 같은 부품 둘을 **코퍼스 빈도의 역수** 로 가중한다. 유사도가
  아니라 빈도다. **"FOCUS 의 단순판" 으로 쓰면 안 된다** — "가중 평균 계열,
  가중치 출처가 다름" 까지만

이것 하나로 *"초기화 baseline 과 비교하지 않았다"* 는 지적이 사라진다.
새 실험 0건이다.

## W3 — 방어 (약 4h)

### Day 5 — downstream + 한자 프로브

사전 등록은 [`PLAN.md` "downstream 과 한자 프로브"](PLAN.md) (2026-09-13).
이미 있는 체크포인트를 쓴다. **학습 없음.**

두 가지를 한 번에 친다.

```
D3  KMMLU 한자어 밀집 도메인   T2a vs C0        <- 본안
D2  한자 밀집 한국어 BPB       787문서 6.71MB   약 10분
D1  같은 부분집합 tok/byte     GPU 0시간
```

**왜 한자 프로브가 필요한가.** T2a 가 제거한 30,000개 중 **13,310개(44.4%)가
한자 포함 토큰** 이다. 의도가 아니라 빈도 필터의 부수 효과다 — `prune.py` 의
`eligible()` 에 유니코드 영역 조건이 없다.

한국어 dev 에서 한자는 **글자의 0.128%** 라 집계 BPB 에 묻혔다. T2a 의 한국어
BPB 가 멀쩡했던 것이 "한자가 괜찮다" 를 뜻하지 않는다 — **측정된 적이 없다.**

절단면은 다행히 간체 전용자 쪽으로 치우쳐 있다 (제거된 단일 한자는 count
중앙값 0 · 최대 7, 생존은 的 人 大 … 國 無 韓). 그래서 **예측은 "차이 없음"**
이다. 그러나 빈도 필터는 *"웹 텍스트에 안 나온다"* 만 보고 **"추론 중간에
쓰인다" 는 구조적으로 못 본다.** 그것이 프로브가 필요한 유일하고 충분한 이유다.

> **KMMLU 로 한다.** KoBEST·HAE-RAE 는 이해·문화 과제라 추론 저하 축을 못 잡고,
> arXiv 2604.16235 가 쓴 것도 KMMLU 다.
>
> **대조는 T2a vs C0 둘만이다.** T2b 를 섞으면 제거 효과와 치환 효과가
> 분리되지 않는다.

> **실행 전에 별도 커밋** 으로 도메인 · 문항 수 · shot · 채점 방식 · 판정
> 경계를 고정한다. 그 커밋이 실행 커밋보다 앞서야 한다.

**틀리면 그것이 값진 결과다** — `prune.py` 의 기준 자체가 반증된다.

### Day 6 — R2 · R3 (선택)

같은 K 로 `random` / `mean` / `permute` (R2), K = 10/40/160/640 (R3).
대조군은 Day 1 것을 재사용한다.

`permute` 가 무게 중심이다. 분포도 노름도 정확히 보존되고 배정만 틀리므로,
회복률이 셋 다 같으면 **"무엇이 틀렸는가" 와 무관하게 벽이 있다** 는 뜻이 된다.

> K>200 에서 영어가 무너진다 (K=300 +3.9%, K=1,000 +29%). K=640 을 보고할 때
> 영어·코드를 함께 적고 **"1차와 같은 종류의 손상" 이라고 부르지 않는다.**

### 남겨 두는 것 — 1.5B CPT · ZeTT

- **1.5B CPT** 는 조건당 0.5B 의 약 3배다. 대조군까지 최소 10시간이라 W3 에
  안 들어간다. 학습 없는 수술 + Pre-CPT BPB 만 하고, *"방향성이 유지된다"*
  이상을 주장하지 않는다
- **ZeTT** 를 못 돌리면 **왜 못 돌리는지를 limitation 에 명시한다.** 우리 결론이
  "초기화로 될 일이 아니다" 이므로, ZeTT 초기화가 같은 벽에 걸리는지가 그
  주장의 외부 검증이다 — 비워 두면 심사자가 먼저 말한다
